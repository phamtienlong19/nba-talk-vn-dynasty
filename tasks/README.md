# tasks/

`tasks/ACTIVE.md` is a generated/local execution pointer at the current
GitHub Issue (or "No active task") — not a second full copy of the
issue. GitHub Issues are the canonical task specification; see
`CLAUDE.md`'s "Task inbox" section.

Generated by `./work-issue.sh <issue-number>`. When a PR merges,
`./sync-after-merge.sh [PR-number]` archives it under `tasks/archive/`
and resets `tasks/ACTIVE.md` to "No active task."

Don't hand-edit `tasks/ACTIVE.md` into a full copy of the issue body or
an essay — that duplicates the issue and goes stale. If you need to work
outside the issue-driven flow, keep it just as short.

## `ACTIVE.md` template (issue-driven)

```markdown
# Active Task

Issue: #N
URL: <issue URL>
Title: <issue title>
Branch: <task branch>
Canonical specification: GitHub Issue #N
Generated: <timestamp>

## Local Constraints
- Read `CLAUDE.md`.
- Preserve project source-of-truth boundaries.
- Do not make unrelated changes.
- Human-decision boundaries in `CLAUDE.md` remain active.
```

## "No active task" template

```markdown
# Active Task

No active task.

Run `./work-issue.sh <issue-number>` to start one.
```

## `tasks/archive/`

One lightweight metadata file per completed task
(`<date>-issue-N-<slug>.md`): issue URL, PR URL, merged commit,
completion timestamp. Not the full task pointer — Git history already
has that.
