# Project context — NBA Talk VN Dynasty (quick orientation for agents and chats)

Snapshot: 2026-10-19, `main` at `6dbe02c` (PR #58 merged). Read `CLAUDE.md` first for the operating rules; this file is the map.
Anything here can go stale: Git history, `data/`, and `ai_exchange/CURRENT_STATE.json` win over this document.

## What this is
A public, static website (GitHub Pages) for a 16-team **fantasy basketball dynasty league** (Yahoo salary-cap format) run by a
Vietnamese friend group. It shows rosters, payroll against a cap band, trades, the draft archive and "what if" views.
It replaced a spreadsheet + a hand-built announcement page. Live: <https://phamtienlong19.github.io/nba-talk-vn-dynasty/>
(repo `phamtienlong19/nba-talk-vn-dynasty`, public). A separate **private** repo `nba-talk-vn-lottery` holds a
lottery ceremony tool — never modify it from here.

## Season phase (now)
The 2026–27 **draft is complete** (48 picks, 19 rookies). The league is in the **regular season**: the app is a maintained
roster / cap / trade reference. Live draft room code exists but is shelved. FA/DRAFT 60 board and Picks page are retired from view.

## Three state layers (the core idea) — `docs/SEASON_STATE_MODEL.md`
| Layer | Meaning | Where |
|---|---|---|
| A. Historical official | keeper freeze + pre-draft trades + 48 draft picks. Must stay reproducible | `keeper_freeze.json`, `trades.json`, `draft_state.json`, `snapshots/POST_DRAFT.json` |
| B. Current season | latest verified roster snapshot + completed in-season trades. The page's default view | `rosters/`, `season_transactions.json` |
| C. Trade Lab scenario | B + ticked proposals; never written | computed in `scripts/season_state.py` |

Ownership is **derived by replaying transactions**, never hand-edited. Corrections are dated amendments, not silent edits.

## Rules that matter (do not "simplify" these)
- **Cap band 131–178** (`config/cap_policy.json`; formula says 177, official policy 178).
- **Payroll = the top 9 salaries per roster, IL included** (league owner decision, 2026-10-16). Players beyond the top 9 don't count.
  Draft-night history keeps the all-player totals recorded at the time.
- **Salaries are frozen** for 2026–27 in `data/2026-27/salary_freeze.json` (a Yahoo refresh must not change payroll).
- In-season trades must move a team **toward** the band; adds/drops may leave it. No fixed roster size in-season (draft night was 12).
- Under-floor teams at the post-draft / post-deadline checkpoints are findings; penalties are a **commissioner** decision.
  DonTrick is 8 below the floor at the post-draft checkpoint (finding only).
- Player identity = **Yahoo player key** (`478.p.<id>`); six drafted rookies not in Yahoo yet are `provisional:*` entries.
- Full rules model: `docs/LEAGUE_RULES_MODEL.md`; open questions: `docs/OPEN_RULE_QUESTIONS.md`.

## Commands
```
python3 -m unittest discover -s tests      # all tests
./validate.sh                              # site validation
python3 scripts/season_state.py status     # snapshot, transactions, payroll, findings
python3 scripts/build_league_state.py sync-ledger && python3 scripts/build_league_state.py embed && python3 scripts/what_if.py embed
./handoff.sh                               # regenerate ai_exchange/REVIEW_PACKET.md
```
After changing data, re-run the embed commands (they are idempotent) — the page reads embedded JSON, not the data files.

## Working agreements (from the owner; they've been enforced repeatedly)
1. **One branch per task from the latest `main`; open the PR into `main`; never merge** — the owner merges. Do not stack PRs on
   other feature branches (this orphaned changes twice). After the owner merges, check the change is actually in `origin/main`.
2. **Don't decide league rules, disputed trade fairness, or official corrections.** Surface conflicts and stop. If an instruction
   contradicts canonical data (e.g. a trade direction), report it; don't silently reinterpret.
3. **Keep internal notes off the public page** (corrections, provenance, direction checks). The embedded data deliberately omits them.
4. Phone-first UI: check ~390 px width; light wording, symbols over sentences; numbers in Roboto Mono; Inter/Roboto Mono only
   (no proprietary fonts). Rookies keep purple styling everywhere, including after trades; the defending champion gets a crown.
5. Regenerate generated files (`index.html` blocks, `REVIEW_PACKET.md`) instead of hand-editing them.
6. The working tree may contain the owner's uncommitted edits — never revert or commit them; use a `git worktree` for clean branches.
7. Use progressive context loading (`CLAUDE.md` → `CURRENT_STATE.json` → `tasks/ACTIVE.md` → search, don't read everything).
