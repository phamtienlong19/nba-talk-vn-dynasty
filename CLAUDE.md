# CLAUDE.md

Operating rules for any Claude Code session working in this repository.

## Start here, in order

1. `CLAUDE.md` (this file)
2. `ai_exchange/CURRENT_STATE.json`
3. `tasks/ACTIVE.md`
4. relevant `docs/` and `data/`
5. source code/scripts relevant to the task

Do not rely on a previous conversation as the only source of project
state. Anything another agent needs must be written into repo data,
`docs/`, `tasks/`, `ai_exchange/`, Git history, or the PR — not carried
only in chat context.

## Task inbox

GitHub Issues are the canonical task specification. `tasks/ACTIVE.md` is
a generated/local execution pointer at an issue (see `./work-issue.sh`
below) — not a second full copy of the issue body. When there's no
active issue, it holds a concise "No active task" state.

Human workflow: **New GitHub Issue → `./work-issue.sh N` → review PR →
merge → `./sync-after-merge.sh PR`**. See `README.md` for the commands.

## Project boundary

This repo is `nba-talk-vn-dynasty`. It is separate from
`nba-talk-vn-lottery`. Never modify the Lottery project unless an
explicit task says so.

## Source hierarchy

- **Forensic roster snapshot** (`local_sources/`, gitignored) → team
  identities/order + pre-keeper ownership baseline only. Its projected-
  keeper tables, old cap analysis, and other analytical sections are
  **not** canonical — see `docs/SOURCE_MANIFEST.md`.
- **Yahoo public source** → current player metadata: NBA team,
  positions, O-Rank, cap dollars. See `docs/YAHOO_DATA_SOURCE.md`.
- **Rules DOCX-derived docs** (`docs/LEAGUE_RULES_MODEL.md`,
  `docs/RULE_AUTOMATION_MATRIX.md`) → governance model.
- **Legacy XLSX-derived docs** (`docs/LEGACY_XLSX_REPLACEMENT.md`) →
  spreadsheet behavior/formulas being replaced, not a live source.
- **Canonical repo data** (`data/`) → current normalized league state
  once promoted.
- **`index.html`** → current deployed presentation until the generated-
  board migration (V2) is complete.

Do not allow stale forensic cap/keeper projections to override current
canonical state.

## Human-decision boundary

Do not autonomously decide:

- league-rule changes;
- commissioner judgment;
- disputed trade fairness;
- tanking intent;
- promotion of a newly changed Yahoo cap snapshot to official;
- canonical roster ownership changes based only on external metadata;
- destructive correction of historical state.

Software/agents may surface evidence and propose changes. Humans
approve governance/state changes.

## Default implementation behavior

For non-trivial tasks:

```
read state
→ read ACTIVE task
→ create/use task branch
→ implement
→ validate
→ update handoff state
→ produce REVIEW_PACKET
→ open/update PR if gh is available/authenticated
```

Do not produce giant prose reports when structured repo artifacts can
carry the information. Keep `tasks/ACTIVE.md` and
`ai_exchange/REVIEW_PACKET.md` concise — regenerate, don't accumulate.

## Handoff artifacts

- `ai_exchange/CURRENT_STATE.json` — machine-readable current
  operational state.
- `ai_exchange/IMPLEMENTATION_REPORT.md` — concise description of what
  the latest implementation accomplished.
- `ai_exchange/REVIEW_PACKET.md` — current delta prepared for another
  agent/human to review. Regenerated by `./handoff.sh`, not hand-authored.
  To surface real (non-empty) "Issues" / "Decisions Required" content,
  write it to `ai_exchange/REVIEW_NOTES.md` (optional, `## Issues` /
  `## Decisions Required` sections) before running `./handoff.sh` — it
  splices that in rather than you hand-editing the packet.
- `ai_exchange/ARTIFACT_MANIFEST.json` — artifact hashes/provenance.
- `build.json` (repo root, public) — deployment-freshness fingerprint;
  see `docs/DEPLOYMENT_FRESHNESS.md`.

Avoid four files repeating the same essay.

## Standard commands

```bash

```

## No hidden context dependency

Everything another agent needs to pick this project back up should be
recoverable by reading this repo — not by having seen a prior chat.

## Context / token discipline

Use progressive context loading.

Start with:
1. `CLAUDE.md`
2. `ai_exchange/CURRENT_STATE.json`
3. the selected GitHub Issue or `tasks/ACTIVE.md`
4. `git status`, `git diff`, and files directly implicated by the task

Do not read all of `docs/`, all of `data/`, historical source files, or prior
implementation reports by default.

Read additional files only when:
- the active task directly references them;
- a source-of-truth question requires them;
- a failing test or dependency requires investigation.

Prefer:
- targeted `rg` / grep;
- `git diff`;
- narrow file reads;
- canonical normalized data;
- existing structured state.

If canonical repo data answers a question, do not reopen the raw DOCX/XLSX/
forensic source.

Do not restate durable project context in task files, PR descriptions, or
handoff reports. Reference the canonical file instead.

Use subagents only when work is genuinely parallel or benefits from isolated
context. For small fixes, targeted investigations, and sequential tasks, work
directly.
